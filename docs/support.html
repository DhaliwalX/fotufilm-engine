Build support

Build requirements

Install Xcode 26 or newer and select it with xcode-select. Install Halide with Homebrew, or set HALIDE_ROOT to a compatible installation.

The Final Cut plugin also needs Apple's FxPlug SDK. Without it, the Mac build includes only the Resolve plugin. You can still run the Final Cut test harness without the SDK.

Start CI manually in GitHub Actions. Rendering and plugin tests need a working Metal device.

Browser editor setup

Install Emscripten, Halide, and Python 3.10 or newer. Set EMSDK_ROOT to the Emscripten SDK directory and run tools/build-wasm.sh. In web, run npm ci and npm run dev for local editing, or npm run build for the production files in web/dist. Runtime modules, film packs and stage files must be deployed with the frontend.

For WebGPU, build the compatible Halide toolchain with tools/build-halide.sh --webgpu before building WASM. The browser probes the GPU renderer and falls back to the CPU when it cannot run. Normal uses the shared Halide plain pipeline compiled to WebAssembly SIMD; rebuild the CPU runtime along with the frontend to enable it. Initial GPU shader compilation can take several seconds. Subsequent edits reuse the renderer and prepared image, with adaptive preview resolution during drags. Small film thumbnails use Halide on the CPU so their shader startup cannot stall active edits. Use HTTPS or localhost. The photo itself is never uploaded.

The WASM build also runs tools/build-raw-wasm.sh, which downloads the checksum-pinned LibRaw 0.22.2 source and builds the local RAW decoder. It can be run separately after setting EMSDK_ROOT. Publish the entire web/public/raw directory with the frontend, including decoder modules and licence notices; Vite copies it to dist/raw. The decoder uses an ordinary worker and does not require cross-origin isolation or shared memory. No RAW files are uploaded. See the LibRaw camera list; support for a camera does not imply support for every compression mode.

If the film library cannot load, check that packs/index.json and the matching runtime files are present under the app’s base URL. When publishing under a subdirectory, set FOTUFILM_BASE for the Vite build. Rebuild packs and modules together after engine changes. npm run check:engine verifies the browser’s configuration layout against the native header.

npm test checks edit history, crop geometry and color controls. npm run test:browser requires Google Chrome and built runtime assets; it checks actual WebGPU and CPU rendering, continuous slider updates before release, Halide Normal agreement with the reference, controls, crop, export, generated RAW fixtures and mobile layout. Set FOTUFILM_TEST_RAW to a local camera file to include the camera RAW smoke test. Against a served production build, run node tools/test-raw-built.mjs http://localhost:5757/ (or its subdirectory URL) to verify decoder loading, mixed imports and full-resolution RAW export. See the browser editor guide for supported features and file formats.

Film packs

Packs loaded in the Mac app are also available in the Fotufilm plugins on the same Mac and user account. Restart Resolve or Final Cut Pro after loading or updating a pack. Install matching app and plugin versions; older plugins skip packs that require a newer release.

Default source builds include all 40 film profiles and their CC BY-SA 4.0 licence notices. No licence key or activation is needed.

Download for Mac ·

The build verifies the Stocks folder against the released profile manifest and file hashes. For a modified source distribution, update the manifest and provenance hashes along with the profiles, and identify your changes under CC BY-SA 4.0. You can also import custom packs through the app.

Custom stock definitions require schema version 1. Sampled spectral rows must contain 81 values from 380 to 780 nm at 5 nm spacing. Coupler geometry must state its two interlayerTransmission values. Older 41-sample rows and range-only coupler definitions are no longer converted during import; export them again in the current format.

Disabled Resolve controls

Check Stage, Resolved Format, Resolved Medium, and Effective Renderer. Custom Mottle needs Full and clump-field grain. Discs needs a silver-image film and Reference mode.

The app and both plugins use the same paper and print-film names in Output Medium. In the source distribution, the model descriptions identify the analytic example receivers.

Negative Only produces density data. To view a negative image, choose Full and set Output Medium to Negative.

Custom builds

For a custom pack build, set both FOTUFILM_PACK_KEY_SOURCE and FOTUFILM_SEALED_PACKS to absolute paths outside this checkout. Both are required. Keep secret pack keys out of version control.

To add supplied packs while retaining the source app’s bundle identifier, keychain service, and imported-pack library, set FOTUFILM_USE_SOURCE_IDENTITY=1. This changes identity selection only; the configured sealed packs still determine the bundled catalogue.

Run python3 tools/check-source-boundary.py before adding files. Record the source and hash of new images, data, and third-party headers in SOURCE_ASSETS.json.

Flat Swift builds must add -ISources/FotufilmHalide/include to import the C bridge declarations. The supplied Mac and plugin scripts already do this; Swift Package Manager discovers the module automatically.

Pack versions

Pack releases can include version and minimumMacAppVersion, using one to three numbers separated by dots. Packs without these fields still work.

When sealing a pack, use --pack-version 1.0.0 --minimum-mac-app-version 1.6. Keep the same pack ID for updates. Increase the pack version when its films change, and increase the minimum Mac version when those changes need a newer app. App releases before this check ignore the new tag.
