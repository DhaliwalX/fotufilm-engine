Build support

Build requirements

Install Xcode 26 or newer and select it with xcode-select. Install Halide with Homebrew, or set HALIDE_ROOT to a compatible installation.

Run python3 tools/test-engine.py to build and run the complete release test suite. It retains up to eight test workers and verifies that every discovered test ran exactly once. Use --workers 2 to reduce concurrency. Logs and the timing report are in build/engine-tests; the report balances later runs without skipping tests. The standard swift test -c release --parallel command also remains supported.

On macOS, the test command caches compiled Halide kernels in .build/compiled-kernels. First runs and runs after relinking need fresh compilation. Remove that directory to clear the test cache, set FOTUFILM_COMPILED_CACHE=0 to disable it, or set FOTUFILM_COMPILED_CACHE_DIRECTORY to a private directory owned by your user. Other Swift package clients use fotufilm-compiled-kernels-v1 under the macOS user cache directory by default. The cache contains code only, never images or rendered results. Missing or invalid entries are rebuilt. Unsafe or unwritable directories, or an unavailable compiler, fall back to normal JIT compilation. Select a full Xcode installation to enable persistent compilation.

Mac, Resolve, and Final Cut rebuilds check source and header contents, compiler settings, and SDK dependencies before reusing compiled objects. Bundle assembly, signing, audits, and requested tests run each time. To force recompilation, set FOTUFILM_BUILD_CACHE=0 or remove build/macos/obj, build/resolve/obj-*, and build/finalcut/obj-*.

Apple AOT generation first downloads matching, checksum-verified kernels from the public engine releases. Downloads need no GitHub token or installed Halide. The cache follows the generator’s source includes and compiler recipe; changing only the CPU implementation or host shim does not regenerate Metal kernels. Set FOTUFILM_AOT_REQUIRE_PREBUILT=1 for a compiler-free AOT step in CI; if the expected release is missing, run the engine’s Apple AOT releases workflow on main and wait for it to finish. Local builds can instead generate with HALIDE_ROOT; use FOTUFILM_AOT_NO_FETCH=1 to explicitly test the local compiler. See the AOT build guide for supported targets and publishing.

The Final Cut plugin also needs Apple's FxPlug SDK. Without it, the Mac build includes only the Resolve plugin. You can still run the Final Cut test harness without the SDK.

Engine checks run automatically on pull requests and pushes to main. Start the workflow manually in GitHub Actions to also check desktop apps, plugins, AOT parity, and the website. Rendering and plugin tests need a working Metal device.

Browser editor setup

Install Emscripten, Halide, Python 3.10 or newer, and the Swift 6.3.3 release toolchain with its matching WebAssembly SDK. Set EMSDK_ROOT to the Emscripten SDK directory and run tools/build-wasm.sh. In web, run npm ci and npm run dev for local editing, or npm run build for the production files in web/dist. The editor uses Astryx 0.5.3 and its Neutral theme; npm ci installs the pinned components and their prebuilt styles. Runtime modules, film packs and stage files must be deployed with the frontend.

The on-device film profile builder uses the same Swift engine as the native editors. Install its SDK with swift sdk install https://download.swift.org/swift-6.3.3-release/wasm-sdk/swift-6.3.3-RELEASE/swift-6.3.3-RELEASE_wasm.artifactbundle.tar.gz --checksum cabfa08b73bb8ac783927ecd15fa386e99d0c139c5f232445067bcf58379cae7. Use the matching release compiler, rather than the Xcode compiler, for cross-compilation. FOTUFILM_SWIFT_WASM_COMPILER can select its executable. tools/build-web-profile.sh builds the worker module and copies only public source stock records and the reflectance resource into web/public/profile. The generated catalogue carries each film’s measured development steps, halation return, stated shutter choices and compatible print controls. Rebuild it with the worker whenever the native control catalogue or film records change. Deploy that entire directory. Requests contain film settings, never image pixels; a worker prepares native configurations and spectral tables locally. The native reference executable is built with swift build -c release --product fotufilm-web-profile.

Photo frames use the native PrintFrameConfiguration and shared PrintFramePlacement through the same profile worker. Rebuild tools/build-web-profile.sh and deploy the complete generated asset set when changing the frame model. The browser composites materials at the final 8-bit sRGB delivery boundary; photographic pixels are copied at integer coordinates. Native and browser font/texture rasterization can differ slightly. Run npm run test:browser -- print-frame.spec.js for native/WASI placement, pixel-preservation, transmission, saved-edit and export checks. Framed delivery is bounded to 120 megapixels and 32,768 pixels per side; choose a smaller export size when added material exceeds that limit.

Auto Adjust runs the native AutoAdjustment solver in the profile worker. Rebuild tools/build-web-profile.sh and deploy its complete output when updating this feature. The browser measures a neutral regional meter on the decoded, corrected frame and sends at most 4,096 brightness statistics; image pixels stay outside the profile worker. The shared native code computes film latitude and exposure/highlight/shadow values. The HDR production smoke test also exercises Auto against the deployed worker.

The browser sample is demo-scene.exr, generated directly as scene-linear Rec.2020 float32 data by tools/generate-demo-exr.py during the WASM build. Deploy it with the frontend and EXR worker. For a quick asset refresh, run python3 tools/generate-demo-exr.py web/public/demo-scene.exr. EXR import runs locally in a worker and preserves floating-point scene values; the display preview is separate. A decoder or file error is shown explicitly.

For local-network previews, run npm run serve in web. The static host uses HOST (default 0.0.0.0) and PORT (default 5757). Another device needs HTTPS for browser cryptography, WebGPU and video APIs: set both FOTUFILM_TLS_CERT and FOTUFILM_TLS_KEY to a certificate and private key valid for the local address. Keep keys outside source control. A self-signed development certificate requires browser confirmation or device trust. Set FOTUFILM_DIST to a frozen production-build directory to keep the shared preview stable while developing another revision. The server serves static files only; photos are processed on the viewing device.

For WebGPU, build the compatible Halide toolchain with tools/build-halide.sh --webgpu before building WASM. The browser probes the GPU renderer and falls back to the CPU when it cannot run. Normal uses the shared Halide plain pipeline compiled for WebGPU and WebAssembly SIMD; rebuild the CPU runtime along with the frontend to enable it. Initial GPU shader compilation can take several seconds. Subsequent edits reuse the renderer and prepared image, with adaptive preview resolution during drags. Film thumbnails share the session’s background engine and use WebGPU after its shader family is ready; CPU previews remain available during compilation. Use HTTPS or localhost. The photo itself is never uploaded.

The WASM build runs tools/build-hdr-wasm.sh to build the checksum-pinned libultrahdr 2.0.2 JPEG gain-map decoder. It can be run separately with EMSDK_ROOT. Deploy the entire web/public/hdr directory, including the decoder and licence notices; Vite copies it to dist/hdr. JPEG imports require this runtime even when a file has no gain map. HEIF/AVIF gain-map decoding is not enabled. The worker releases its decoder heap when an import finishes, fails or is cancelled. Generate synthetic test images with bash tools/build-hdr-test-fixtures.sh after building the decoder; this needs CMake, a native Clang compiler and libjpeg. Then run npx playwright test test/editor/hdr.spec.js in web. Against a served production build, run node tools/test-hdr-built.mjs http://localhost:5757/ from the repository root (or supply its subdirectory URL) to verify both HDR and EXR worker bundles, decoder revisions, orientation and export.

The WASM build also runs tools/build-raw-wasm.sh, which downloads the checksum-pinned LibRaw 0.22.2 source and builds the local RAW decoder. It can be run separately after setting EMSDK_ROOT. Publish the entire web/public/raw directory with the frontend, including decoder modules and licence notices; Vite copies it to dist/raw. Rebuild and publish both together when updating the decoder: the frontend requires its scene-exposure scale and reports an error if an older runtime lacks it. Reload the editor and reopen existing RAW photos to apply decoder changes. The decoder uses an ordinary worker and does not require cross-origin isolation or shared memory. No RAW files are uploaded. See the LibRaw camera list; support for a camera does not imply support for every compression mode.

The WASM build also runs tools/export-web-media.py. It exports output-medium packs and pipeline stages from the native engine, stores compressed differences under packs/media, and writes packs/media.json. Publish these assets alongside the base packs. The browser verifies both base and reconstructed file hashes; assets from different builds are rejected. A medium is fetched on first use and cached for subsequent edits.

If an update leaves the browser reporting an aborted renderer, reload the page. Published builds now version the JavaScript modules, WASM binaries, film packs and worker data together. Failed runtime loads are retried rather than retained for the session. Browsers without WebAssembly JavaScript Promise Integration use the CPU film renderer even when they expose WebGPU.

If a local build reports a missing or stale strict-float implementation, rebuild Halide with tools/build-halide.sh --webgpu, then rerun tools/build-wasm.sh. The CPU reference fixes floating-point evaluation order, and the WebGPU compiler carries matching arithmetic. The build checks the compiler patch and shader hashes. See tools/webgpu-parity/README.md in the source checkout for comparisons before display conversion; diagnostic modules are omitted from production builds.

If the film library cannot load, check that packs/index.json and the matching runtime files are present under the app’s base URL. When publishing under a subdirectory, set FOTUFILM_BASE for the Vite build. Rebuild packs and modules together after engine changes. npm run check:engine verifies the browser’s configuration layout against the native header.

To rebuild only the GPU runtime after preparing the patched compiler, run bash tools/build-webgpu-wasm.sh. This includes Normal and the complete film/grain kernels. Publish both fotufilm-webgpu.mjs and fotufilm-webgpu.wasm; missing files cause a CPU fallback. The backend readout reports the renderer actually used. Development runs in a worker, including the CPU fallback.

TIFF import uses the pinned libtiff and Little CMS decoder built by bash tools/build-tiff-wasm.sh. It supports integer 1/2/4/8/16-bit and float32 TIFF, common lossless compression, JPEG YCbCr, strips, tiles and file orientation. CMYK needs an embedded ICC profile; unsupported encodings report an error. Deploy web/public/tiff/ with its codec licence notices. These decoders preserve high-bit-depth samples instead of passing through an 8-bit canvas.

Automatic negative conversion needs bash tools/build-negative-wasm.sh and bash tools/build-web-profile.sh, both included in the complete browser build. Deploy web/public/negative/ and web/public/profile/ together. Conversion prefers WebGPU and falls back to WebAssembly SIMD in a background worker. Metal and CPU kernels are also generated by the Apple AOT build.

Build the lossless 16-bit PNG decoder with bash tools/build-png-wasm.sh (also included in tools/build-wasm.sh). It compiles pinned libpng and Little CMS sources with Emscripten. Deploy the complete web/public/png/ directory, including codec licence notices. Missing or invalid runtime files produce an import error instead of reducing a deep PNG to 8-bit samples.

Still canvases request Display P3 and confirm the actual context attributes. Browsers without that support use sRGB previews and canvas exports; TIFF writes a Display P3 profile directly and does not require a wide-gamut canvas. Photo geometry uses floating-point canvas samples when supported. The small sRGB and Display P3 ICC resources can be regenerated with python3 tools/generate-web-color-profiles.py using Little CMS 2; set LCMS2_LIBRARY if its shared library is not discoverable.

npm test checks edit history, crop geometry and color controls. npm run test:browser requires Google Chrome, built runtime assets and the release CLI; it checks actual WebGPU and CPU rendering, continuous slider updates before release, Halide Normal agreement with the reference, output-medium selection and agreement with native packs, controls, crop, export, generated RAW fixtures and mobile layout. Set FOTUFILM_TEST_RAW to a local camera file to include the camera RAW smoke test. Against a served production build, run node tools/test-raw-built.mjs http://localhost:5757/ (or its subdirectory URL) to verify decoder loading, mixed imports and full-resolution RAW export. See the browser editor guide for supported features and file formats.

The RAW build also builds the native CLI and exports the bundled measured camera corrections to web/public/raw/camera-profiles.json, with CAMERA-PROFILES-LICENSE.txt. Deploy these with the decoder. Missing or invalid camera assets produce an import error. Rebuild the RAW runtime when the native camera profiles, correction solver or white-balance locus change.

The browser engine build also runs bash tools/build-web-scene.sh. This exports the native exposure-domain spectra and film sensitivities to web/public/packs/scene, with their notices. Publish the entire directory with the packs. Its roughly 9 MB compressed reconstruction is loaded once on the first film render with an explicit Source Illuminant. A worker integrates and caches each film/light combination; ordinary edits reuse the result. The geometry.spectra file contains gzip data decoded by the worker and must be served as a binary file without a Content-Encoding: gzip header. Missing or mismatched assets report an error. Rebuild these assets when changing the reconstruction, spectral domain, film sensitivities or reference illuminants.

Browser lens correction uses the portable native DNG parser and lens catalogue in the profile worker. Rebuild tools/build-web-profile.sh and tools/build-raw-wasm.sh together after lens metadata changes. JPEG, PNG, WebP and TIFF/DNG capture tags are read without copying photo pixels into the profile worker. LibRaw provides additional RAW lens names and capture settings. The DNG correction is normalized to the dimensions actually decoded. Imported Fotufilm lens catalogues are validated on device and kept in IndexedDB; imports and the combined catalogue are limited to 6 MB. No measured lens database ships with the web app. If browser storage is unavailable, an imported catalogue remains usable for that session and the panel explains that it was not saved.

Browser video

Video editing requires a secure context (HTTPS or localhost), WebCodecs decoding, and a supported input codec. Codec availability depends on the browser, operating system and hardware; a filename extension alone does not establish support. HEVC Main / Main10 4:2:0 has a bundled software fallback that preserves native 8- and 10-bit values. Other unavailable codecs report an error before import. Use a current Chrome, Edge or Safari browser; some browsers can edit frames they cannot play with audio. ProRes and raw cinema codecs require a decoder that exposes their native pixels and are not bundled.

Video export also needs WebCodecs encoding and writable file-system storage. Chrome and Edge can write to a file you choose. Browsers with supported origin-private file-system writes stage a disk file and show a download link. If storage is unavailable or full, free disk space or use a browser with file-system access; the editor does not buffer large exports in RAM. Save the download before dismissing it. Cancel stops rendering and discards incomplete output. If the tab or browser crashes, its staging data may remain; clear this site's stored data in browser settings to reclaim it.

For log footage, select the recorded Input color space. The decoder must expose untouched RGB or YUV planes; formats that cannot be read without a browser color conversion fail explicitly. HDR and log input are developed in floating point, but exported videos are 8-bit SDR. Include audio is enabled by default. If an audio codec cannot be copied or transcoded to the selected format, choose another format or explicitly disable audio.

Run npm test for curve, range and edit validation, npm run check:video to compare the generated browser catalog against Swift, and npm run test:browser -- video.spec.js for file-backed import, audio, trim, disk export, cancellation and quota-failure checks. Browser video fixtures require FFmpeg and Chrome. Run the film parity test with the matching public browser runtime assets available. The runtime build also creates the fallback-kernel probe for flexible-renderer.spec.js; rebuild that probe independently with tools/build-wasm-flexible-test.sh. Profile tests use .build/release/fotufilm-web-profile as the native reference.

Film packs

Packs loaded in the Mac app are also available in the Fotufilm plugins on the same Mac and user account. Restart Resolve or Final Cut Pro after loading or updating a pack. Install matching app and plugin versions; older plugins skip packs that require a newer release.

Default source builds include all 40 film profiles and their CC BY-SA 4.0 licence notices. No licence key or activation is needed.

Download for Mac ·

The build verifies the Stocks folder against the released profile manifest and file hashes. For a modified source distribution, update the manifest and provenance hashes along with the profiles, and identify your changes under CC BY-SA 4.0. You can also import custom packs through the app.

Custom stock definitions require schema version 1. Sampled spectral rows must contain 81 values from 380 to 780 nm at 5 nm spacing. Coupler geometry must state its two interlayerTransmission values. Older 41-sample rows and range-only coupler definitions are no longer converted during import; export them again in the current format.

Disabled Resolve controls

Color Management: Timeline shows the existing Timeline Color Space menu. Choose Fotufilm to show separate Input Color Space and Output Color Space menus. Print Only disables Input Color Space because it reads density; Negative Only disables Output Color Space because it writes density. Inactive choices are retained when switching modes.

For direct Apple Log footage in an unmanaged DaVinci YRGB project, choose Fotufilm mode, Apple Log / Rec.2020 input, and Rec.709 / Gamma 2.4 output. Remove surrounding camera conversion CSTs and match Resolve's monitoring and export settings to that output. If Resolve or an upstream node has already converted the image, select the space reaching Fotufilm instead of the camera format. A finished print needs no additional output tone mapping or OOTF. See the Resolve color-management guide for all supported spaces.

Check Stage, Resolved Format, Resolved Medium, and Effective Renderer. Custom Mottle needs Full and clump-field grain. Discs needs a silver-image film and Reference mode.

If an older Resolve plugin produces broad coloured bands, black regions, or an Open FX GPU error when delivering Rec.709 or sRGB, update the plugin and restart Resolve. A failed GPU session also needs a restart. Reference rendering is a workaround until the updated plugin is installed; no exposure or colour-space adjustment is needed to compensate for this rendering defect.

The app and both plugins use the same paper and print-film names in Output Medium. Each receiver is digitised from the manufacturer's own published datasheet, and the model descriptions name the publication.

Negative Only produces density data. To view a negative image, choose Full and set Output Medium to Negative.

Custom builds

For a custom pack build, set both FOTUFILM_PACK_KEY_SOURCE and FOTUFILM_SEALED_PACKS to absolute paths outside this checkout. Both are required. Keep secret pack keys out of version control.

To add supplied packs while retaining the source app’s bundle identifier, keychain service, and imported-pack library, set FOTUFILM_USE_SOURCE_IDENTITY=1. This changes identity selection only; the configured sealed packs still determine the bundled catalogue.

Record the source and hash of new images, data, and third-party headers in SOURCE_ASSETS.json.

Flat Swift builds must add -ISources/FotufilmHalide/include to import the C bridge declarations. The supplied Mac and plugin scripts already do this; Swift Package Manager discovers the module automatically.

Pack versions

Pack releases can include version and minimumMacAppVersion, using one to three numbers separated by dots. Packs without these fields still work.

When sealing a pack, use --pack-version 1.0.0 --minimum-mac-app-version 1.6. Keep the same pack ID for updates. Increase the pack version when its films change, and increase the minimum Mac version when those changes need a newer app. App releases before this check ignore the new tag.
