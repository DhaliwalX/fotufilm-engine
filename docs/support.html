Build requirements & portable codecs

  • macOS & Engine: Install Xcode 26 or newer (selected via xcode-select) and Halide (via Homebrew or HALIDE_ROOT).
  • Final Cut Pro plug-in: Install Apple’s FxPlug SDK to build the installable FxPlug bundle. Without FxPlug, the Mac build packages the DaVinci Resolve OpenFX plug-in and can still run the Final Cut test harness (./finalcut/build.sh --test).
  • Bounded RAW & TIFF checks: Install libraw (0.22.2), little-cms2, libtiff (4.7+), clang++, and Node.js, then run tools/test-raw-codec.sh and tools/test-tiff-codec.sh to verify synthetic DNG and TIFF decoding under AddressSanitizer and UBSan. See Sources/CFotufilmCodecs/README.md.

Running tests & kernel caches

Run the parallel release test runner to verify that every discovered test executes cleanly:

python3 tools/test-engine.py           # up to 8 workers; writes logs to build/engine-tests
python3 tools/test-engine.py --workers 2
swift test -c release --parallel       # standard SwiftPM runner
  • Compiled kernel cache: On macOS, tests cache compiled Halide kernels in .build/compiled-kernels (and SwiftPM clients use fotufilm-compiled-kernels-v1 under the user cache directory). The cache stores compiled code only—never images or edit data. Set FOTUFILM_COMPILED_CACHE=0 to disable it, FOTUFILM_COMPILED_CACHE_DIRECTORY to override its location, or delete .build/compiled-kernels to force fresh compilation.
  • Incremental native builds: Desktop, Resolve, and Final Cut build scripts hash sources, headers, compiler flags, and SDK versions before reusing objects. Set FOTUFILM_BUILD_CACHE=0 or remove build/engine/obj, build/resolve/obj-*, and build/finalcut/obj-* to force a clean rebuild.

Apple AOT & prebuilt kernels

Apple ahead-of-time (AOT) build scripts automatically download matching, checksum-verified Metal and CPU kernel archives from public GitHub releases—no GitHub token or local Halide compiler required:

  • Set FOTUFILM_AOT_REQUIRE_PREBUILT=1 in CI to enforce compiler-free AOT downloads (if a hash is new on main, trigger the Apple AOT releases workflow first).
  • Set FOTUFILM_AOT_NO_FETCH=1 with HALIDE_ROOT configured to compile all AOT variants locally. See README.md — Apple AOT kernels.

Browser editor setup (WASM & WebGPU)

Building the self-hosted browser editor requires Emscripten (EMSDK_ROOT), Halide (built with tools/build-halide.sh --webgpu for WebGPU shader generation), Python 3.10+, Node.js 22+, and the Swift 6.3.3 release toolchain with its matching WebAssembly SDK:

# 1. Install the Swift 6.3.3 WASM SDK
swift sdk install \
  https://download.swift.org/swift-6.3.3-release/wasm-sdk/swift-6.3.3-RELEASE/swift-6.3.3-RELEASE_wasm.artifactbundle.tar.gz \
  --checksum cabfa08b73bb8ac783927ecd15fa386e99d0c139c5f232445067bcf58379cae7

# 2. Build WASM/WebGPU runtimes, codecs, scene tables, and Swift profile worker
./tools/build-wasm.sh
./tools/build-web-profile.sh

# 3. Install web dependencies and bundle the production Flutter web app
(cd web && npm ci && npm test)
(cd flutter && ./tool/build-web.sh --assets ../web/public)

# 4. Serve locally over localhost
(cd flutter && node tool/serve-web.mjs)

Deployed runtime directories

Always rebuild and deploy runtime directories together after engine or catalog changes so versioned JS/WASM hashes match:

  • packs/ & packs/media + packs/scene: Film packs, output-medium deltas (tools/export-web-media.py), and spectral scene tables (tools/build-web-scene.sh; serve geometry.spectra as raw binary without Content-Encoding: gzip).
  • profile/: On-device Swift WASM profile builder, frame placement model, Auto Adjust solver, and DNG lens metadata parser (receives settings and brightness stats only—never image pixels).
  • hdr/, raw/, tiff/, png/, negative/, library/: Pinned worker decoders (libultrahdr 2.0.2, LibRaw 0.22.2 + camera spectral profiles, libtiff + lcms2, libpng + lcms2, negative scan preparation, and Halide library thumbnail resampler) with their license notices.

Serve over HTTPS or localhost so WebGPU and WebCodecs are enabled. If a GPU shader step stalls for 90 seconds or a browser lacks WebGPU / JSPI support, the worker falls back to SIMD WebAssembly on the CPU automatically. Run npm run check:engine and npm run test:browser in web/ to verify Chrome WebGPU/CPU parity.

Browser video & storage

Browser video editing uses WebCodecs for local chunked decoding and disk-backed encoding (writing directly via the File System Access picker in Chrome/Edge or staging in origin-private storage elsewhere, without buffering full movies in RAM). HEVC Main / Main10 4:2:0 includes a bundled software fallback that preserves 8- and 10-bit planes; ProRes and raw cinema formats are not bundled. Exported browser videos are 8-bit SDR MP4 (H.264) or WebM (VP9) with synchronized audio.

Vulkan parity diagnostics

tools/vulkan-parity compares CPU and Vulkan rendering on an authorized arm64 Android device using an Android NDK and Vulkan-capable Halide toolchain. By default it checks against browser image-quality tolerances while recording float, 8-bit, and 16-bit byte deltas; pass --exact to require byte-identical output. See tools/vulkan-parity/README.md for setup and Linux software-Vulkan notes.

DaVinci Resolve & Final Cut troubleshooting

  • Disabled color-space menus: Under Color Management: Timeline, only Timeline Color Space is shown. Switch to Fotufilm mode to unlock separate Input Color Space and Output Color Space menus. Note that Print Only ignores Input Color Space (it reads density) and Negative Only ignores Output Color Space (it writes density; to view a negative visually, keep Stage on Full and set Output Medium to Negative).
  • Direct Apple Log setup: In an unmanaged DaVinci YRGB project, set Color Management to Fotufilm, Input to Apple Log / Rec.2020, and Output to Rec.709 / Gamma 2.4, removing external camera CSTs and disabling extra output tone mapping.
  • Inactive grain or mottle options: Custom Mottle requires Full stage and clump-field grain; silver Discs require a monochrome silver stock and Reference renderer mode. Check Stage, Resolved Format, Resolved Medium, and Effective Renderer at the bottom of the inspector.
  • GPU banding or OpenFX errors on older builds: Update both the desktop app and plug-ins to the current release and restart Resolve (a failed OpenFX GPU session requires a host restart).

Custom builds & pack manifests

  • Source identity & flat builds: All source builds bundle the complete 47-film catalog. Set FOTUFILM_USE_SOURCE_IDENTITY=1 if an official build should retain the source bundle identifier and keychain service. Flat swiftc invocations outside SwiftPM must pass -ISources/FotufilmHalide/include.
  • Asset provenance: Record the provenance and SHA-256 of any new image, dataset, or third-party header in SOURCE_ASSETS.json, and update the profile manifest alongside any modified stock files under CC BY-SA 4.0.
  • Custom stock schema & pack versions: Custom authored JSON stocks use schema version 1 with 81 spectral samples (380–780 nm at 5 nm spacing) and explicit interlayerTransmission pairs. Sealed packs may declare optional --pack-version and --minimum-mac-app-version tags. See LICENSING.md.
